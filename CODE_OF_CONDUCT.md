# Code of conduct

## The short version

Be straight with people, and be straight about evidence. Those are the same
rule here.

## What is expected

- **Disagree about the evidence, not the person.** "That figure cites page 7
  and the row is on page 9" is the conversation this project wants. "You clearly
  did not read it" is not.
- **Say what you actually checked.** If you ran the command, say so. If you are
  going on a hunch, say that instead. A confident wrong claim costs more here
  than an admitted gap, because the whole product is the difference between the
  two.
- **Assume the other person read the source.** Frequently they did, and the
  measurement was wrong. This has already happened in this repository more than
  once.
- **Take correction well.** Publishing your own withdrawn claims is normal
  practice here — see `DIRECTOR-REVIEW.md`. Nobody is keeping score.

## What is not acceptable

Harassment, personal attacks, demeaning comments, or unwelcome attention.
Publishing someone's private information. Sustained disruption of discussions.
Any conduct that would reasonably make someone stop contributing.

Two that are specific to this project:

- **Do not post personal information about taxpayers.** No property addresses,
  roll numbers, owner names, or account numbers in issues, fixtures, commits, or
  pull requests. `CONTRIBUTING.md` says this too; it is repeated here because it
  is the one that would do real harm to someone who never chose to be involved.
- **Do not use this project to attack a municipality or an official.** It
  publishes public finance figures with their sources attached. That is the
  whole of it. Contributions framed as building a case against a named person
  will be closed.

## Scope

This applies in the repository — issues, pull requests, discussions, commit
messages — and anywhere someone is representing the project.

## Reporting

Report conduct concerns privately to the repository owner through
[GitHub's private vulnerability reporting](https://github.com/Jstn-1g/what-in-the-tax/security/advisories/new),
which is the only private channel this project currently has. Serious cases can
also go to [GitHub Support](https://support.github.com/contact/report-abuse),
which can act independently of the maintainer.

> **Known gap:** a single maintainer receiving conduct reports about their own
> project is not a real enforcement model, and a published email contact does
> not exist yet. Both are open items before this repository goes public — the
> same `pending-public-contact-channel` that blocks publication in `PUBLISH.md`.
> This section will be wrong until they are fixed, and it says so rather than
> implying a process that is not there.

## Enforcement

The maintainer may edit, hide, or delete contributions, and may block accounts.
Where a decision is about conduct rather than evidence, the reasoning will be
stated publicly unless doing so would expose the reporter.
